0. READ ME FIRST (for Claude Code)
--------------------------------------------------------------------------------

What this is
  NemoThrones is a text adventure set in A Song of Ice and Fire. The player picks
  any canon character and a start year, then lives that life through dialogue
  and decisions until the character dies. There is no objective. Other characters
  are persistent "nemo agents" that act in the background at a level of detail
  set by how relevant they are to the player.

  Canon is A Wiki of Ice and Fire (awoiaf.westeros.org). The game runs on Jack's
  "nemo" stack: NemoClaw + an OpenShell sandbox called "prometheus" + Hermes
  Agent + DeepSeek v4.1 Flash via OpenRouter.

  Core principle: the engine owns the facts; LLMs supply the voice. LLMs propose
  JSON; the Warden validates it; the engine computes odds, rolls the dice and
  commits each turn as one SQLite transaction over an append-only event log.

Read in this order
  1. docs/DESIGN.md, sections 1-3 (principles, architecture, the turn), then
     section 8.1 (the integration points nobody has verified yet)
  2. README.md
  3. src/nemothrones/engine/game.py    the turn pipeline: _execute, _reactions,
                                        _advance, _background, _direct, _narrate
  4. src/nemothrones/engine/odds.py    the probability model
  5. src/nemothrones/engine/warden.py  validation of every LLM output
  6. src/nemothrones/agents/prompts.py the system prompt of every role
  7. src/nemothrones/lore/slicer.py    the past/fate split (spoiler control)
  8. src/nemothrones/world/store.py    event-sourced store, reducers, rebuild()
  9. src/nemothrones/llm/client.py     role routing, fallback, repair retry

Ground rules
  - Never commit API keys, tokens or WOIAF page text. The wiki text is CC BY-SA
    and stays in the local cache (lore.db).
  - Saves are written only by the engine. The Hermes plugin opens them read-only.
  - Fate (canon after the start date) must never reach agent, narrator or GM
    prompts. Keep tests/unit/test_fate_isolation.py green. Only world/fate.py
    reads the fate table, and only allowed modules may import it.
  - Run "ruff check src tests" and "pytest" before every commit.

3. STAGE B - THE LIVE WIKI FROM THE HOST (free)                        [CLAUDE]
--------------------------------------------------------------------------------

The host has open internet (the sandbox does not). This stage checks my
untested assumptions about the WOIAF API and its page markup. It makes polite
requests: at most one per second, on one connection.

    H=~/.nemothrones-dev
    .venv/bin/nemothrones lore probe "Eddard Stark" --home $H

  Expected:
    "infobox_template": "Character"
    "infobox_keys": includes "born", "died", "father", "allegiance" ...
    "sections": includes "Recent Events > A Game of Thrones"
    "is_character": true

  If it fails or looks wrong, fix it and add a test:
    - HTTP/JSON error      check lore.api_url (default https://awoiaf.westeros.org/api.php)
    - template not found   lore/parse.py INFOBOX_RE (template names)
    - keys missing         lore/parse.py CHAR_KEYS; SAFE_INFOBOX in lore/dossier.py
    - sections mis-dated   data/books.yaml (book subsection titles and years)
    - junk in prose        lore/parse.py clean() and SKIP_SECTION_RE
    You may record a small trimmed snippet of real markup as a test fixture if
    needed. Keep it minimal and attributed (CC BY-SA); prefer the synthetic style
    in tests/fixtures/wiki/.

Then:
    .venv/bin/nemothrones lore search "Jon Snow" --home $H
    .venv/bin/nemothrones lore page "Robb Stark" --year 298 --home $H
        # must NOT contain "Red Wedding", "King in the North" or a death date
    .venv/bin/nemothrones lore page "Jon Snow" --year 298 --home $H
        # must NOT contain "Lord Commander" or "Night's Watch" (his future)
    .venv/bin/nemothrones lore cast "Eddard Stark" --year 298 --home $H
        # takes 1-2 minutes; the top ranks should be Ned's kin, Robert, the
        # Lannisters and so on. Nobody dead before 298 should appear.

Cross-check the hand-authored seed pack against the wiki
  File: src/nemothrones/data/seed_packs/winterfell_298.yaml
  It was written from memory of the books. Check:
    - birth years (born_year) for each character
    - the year in each "fate:" text (e.g. Eddard's execution: 298 or 299 AC?)
    - canon_events years. The moons are game estimates; say so if you leave them.
  Fix discrepancies and rerun pytest.

    nemohermes prometheus policy-add --from-file policy/nemothrones.yaml --dry-run
    nemohermes prometheus policy-add --from-file policy/nemothrones.yaml --yes

6. THE INTEGRATION POINTS NOBODY HAS VERIFIED - SYMPTOMS AND FIXES
--------------------------------------------------------------------------------

  inference.local (TLS or routing)
    symptom: doctor "[fail] inference_local"
    fix:     check "nemohermes prometheus status" for inference health. If it is
             a TLS error, set llm.backends.inference_local.ca_bundle in
             /sandbox/.hermes/workspace/nemothrones/nemothrones.yaml to the
             proxy CA bundle (or set SSL_CERT_FILE).

  The Hermes API from inside the sandbox
    symptom: doctor "[fail] hermes", or /debug llm shows gm=inference_local
    checks:  - Does /sandbox/.hermes/workspace/nemothrones/hermes_api_token exist
               (written by start_nemothrones.sh)?
             - Is "nemohermes prometheus gateway-token" the API bearer, or is it
               API_SERVER_KEY in /sandbox/.hermes/.env? The code tries the env
               var, then the token file, then .env.
             - Is 127.0.0.1:8642 reachable inside the sandbox?
                 T=/sandbox/.hermes/workspace/nemothrones/hermes_api_token
                 curl -s http://127.0.0.1:8642/v1/chat/completions \
                   -H "Authorization: Bearer $(cat $T)" -H 'Content-Type: application/json' \
                   -d '{"messages":[{"role":"user","content":"hello"}],"stream":false}'
             - The Hermes reply must be ONE JSON object; see /debug llm errors.
    note:    the game still works on the fallback; this only affects the GM.

  Hermes plugin registration
    symptom: Hermes logs an error at start, or the nt_* tools are missing
    fix:     match _register() in hermes/plugin/nemothrones/__init__.py to your
             Hermes version's ctx.register_tool(...) signature (see the Hermes
             docs: "Build a Hermes Plugin"). Confirm plugins.enabled in
             /sandbox/.hermes/config.yaml.

  Skills location
    symptom: "nemohermes prometheus skill list" lacks nemothrones-gm and woiaf-maester
    fix:     deploy.sh copies them to /sandbox/.hermes/skills/<name>/. Move
             them if your Hermes reads skills from somewhere else.

  WOIAF inside the sandbox
    symptom: doctor "[fail] WOIAF"
    checks:  - "nemohermes prometheus policy-list" shows nemothrones
             - the venv path in policy binaries: matches the real interpreter
               (venvs symlink python -> python3.x; the glob python* covers it)
             - "nemohermes prometheus logs --follow" for denied_action events

  TTY entry
    symptom: "connect" gives a shell, but the game will not start
    fix:     run the full venv path by hand ($G above), or try
             NEMOTHRONES_ENTRY=docker ./scripts/start_nemothrones.sh
             (note: docker exec runs outside the supervisor's process context,
             so inference.local may not resolve there)

  docker exec -u sandbox
    symptom: "unable to find user sandbox"
    fix:     use the uid (998, per the nemo README) in sx() in scripts/deploy.sh
